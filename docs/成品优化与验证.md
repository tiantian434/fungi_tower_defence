# 成品优化与验证

日期：2026年10月20日。版本：`0.1.0-jam`。开发分支：`codex/gamejam-release-optimization`。

开始前发现已有一批未提交的三章优化。本次先新建分支并以 `9880877` 保存完整检查点，再修复、验证和准备发布包；屏幕适配基线为 `168118f`。没有回退或删除此前进度，没有推送或上传平台。

## 玩法与成长

- 第一关由六波收紧为三次有区别的遭遇，总35个敌人。两个固定画架各60能量，第一次回收开放双线生长，160能量改装能力需要结合战斗回收。
- 第二关终端错峰启动，准备和后续压力分层，给前沿建设留出时间；仍需要保护新花苞、选择炮台位置和改装。
- 回流显示本次收到的创作能量，连续收益合并为一个数字；阶段解锁触发连通网络脉冲。收益在事件当帧定位，即刻暂停也能看到。
- 第三关三处记忆替换为已有原画制作的独立画页，显示进度和完成标记。

详细配置和正常路线结果见 [关卡节奏调整](赛前关卡节奏调整.md)。这些调整保持现有资源运输与账目体系，未加入新的经济系统。

## 第一次游玩的流程

- 教学卡直接显示在左下留白，提供“知道了”，也会按阅读时间自动推进。过时的放置教学被当前进展替换，危险和新能力优先展示。
- 暂停、菜单、详情和建造预览遮住教学时保留阅读时间。关内独白暂时让位于教学，避免重叠。
- 两次成长分别记录，不再被同一事件ID去重；第二关补充开局步骤。
- 正式关卡完整拦截F5–F10，避免继续传给旧演示父类而意外切离主线。
- 标题继续与结果页下一章走统一入口，按已读剧情状态补播过场；进度格式升级兼容旧记录。
- CG2合并重复讲述，调整到10幕50秒，围绕外界评价压力过渡到重新掌握创作节奏。CG末幕明确提示继续进入关卡或完成故事。

## 结尾

最后一块记忆收集后，保留三段完整文字供玩家阅读；确认后隐藏战斗与操作杂项，镜头展示本局实际长出的花海。玩家主动进入结尾CG，成绩页可以再次回看同一幅花海。回顾、展示、剧情和成绩之间切换不会重新启动战斗或收集计时。

## 画面、显示和声音

- 世界标签最小字号提高，保留手绘字体和纸面风格。教学避让检查覆盖关键目标的整张图片区域。
- 保留本轮屏幕适配：窗口、无边框全屏、F11/Alt+Enter、切关后保持尺寸，支持16:9、16:10和超宽屏。镜头与可建造边界独立于显示分辨率，地图距离不变。
- 修复静音跨场景、重启后丢失原音量：20%音效和30%音乐静音后再解除，恢复原选择。
- 独立CG播放器改为运行时加载备用音频场景，解决全局类型预加载时捕获不完整场景的问题；加载失败也保留剧情按钮操作。

## 发布包

新增 `Windows Release` 导出预设，使用匹配的Godot4.7.2 Windows x86_64模板，版本为0.1.0-jam，使用花朵与铅笔图标。主程序与同名PCK一起交付；包含玩家说明，排除测试、缓存、开发文档、原始整包素材和构建产物。

动态加载的四段剧情与UI资源全部保留。实际PCK验收发现基础敌人仍依赖原始素材目录中的一张动画图；现已原样复制到运行时素材目录，避免排除原始素材包后导致三关无法加载。

工程README改为当前版本入口，原有逐步开发记录完整保存在 [历史开发记录](历史开发记录.md)，避免旧的六波和占位素材说明混淆当前版本。制作名单按用户要求暂不处理。
